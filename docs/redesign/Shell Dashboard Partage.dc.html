Le contrat du composant

Le shell ne connaît pas les rôles : il reçoit une configuration. Ajouter un espace — partenaire, hôtel, dispatcher de nuit — devient un objet, pas une quatrième barre latérale.

<DashboardShell
  space="Espace chauffeur"   // ligne mono sous le logo
  accent="terre"             // terre pour le chauffeur, lagune ailleurs
  groups={driverNav}         // [{ label, items: [{ href, label, icon, badge }] }]
  title="Tableau de bord"    // titre mono de la barre du haut
  chip={ {tone: "live", label: "En service"} }
>
  {children}
</DashboardShell>
  • La navigation de chaque rôle vit dans un fichier de configuration, à côté de ses routes — pas dans le JSX.
  • Barre du bas mobile dérivée des mêmes groupes, sans deuxième liste à maintenir.
  • Thème clair et sombre, langue et déconnexion : une seule implémentation pour les quatre espaces.

Point d'attention

L'espace entreprise n'a ni barre latérale ni barre du haut : ses six onglets sont une ligne horizontale dans entreprise/dashboard/page.tsx, avec un retour « Mon compte » vers l'espace client. C'est l'espace qui gagne le plus au passage sur le shell, et le seul dont la navigation change vraiment de forme.

Ordre de migration

Chauffeur d'abord — il est déjà dessiné. Puis client, dont la barre latérale est la plus proche structurellement. Entreprise ensuite, qui passe des onglets au cadre. Admin en dernier : douze entrées de navigation et un état d'onglet géré par la page.
